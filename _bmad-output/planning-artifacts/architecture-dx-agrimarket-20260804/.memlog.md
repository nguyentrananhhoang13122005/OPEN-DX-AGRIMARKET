| 6 | decision | AD-1: Paradigm — Layered monolith with service isolation. Next.js handles H-layer (UI + API routes); n8n handles P-layer (automation); PostgreSQL is the Single Source of Truth for D-layer; Ollama+FastAPI are I-layer services. Binds: all cross-layer calls go through defined interfaces. Prevents: frontend calling external APIs directly; business logic leaking into UI components | 2026-08-04 |
| 7 | decision | AD-2: Repository structure — Monorepo with /apps/web (Next.js) and /apps/disease-api (FastAPI). Shared /docker and /workflows (n8n). Binds: all code lives in one GitHub repo; issues track across both apps. Prevents: version drift between apps; duplicate Docker config | 2026-08-04 |
| 8 | decision | AD-3: Frontend framework — Next.js with App Router (Next.js 13+). Binds: file-based routing under /app; Server Components by default, 'use client' directive for interactive components. Prevents: mixing Pages Router conventions | 2026-08-04 |
| 9 | decision | AD-4: ORM — Prisma with PostgreSQL. Binds: schema-first with prisma/schema.prisma; all DB access through Prisma Client; migrations via prisma migrate. Prevents: raw SQL in application code (allowed only for complex reporting queries); multiple DB access patterns | 2026-08-04 |
| 10 | decision | AD-5: Client state management — Zustand. Binds: global UI state in Zustand stores per domain (auth, htx-profile, map, notifications); server state via Next.js fetch/SWR. Prevents: prop drilling beyond 2 levels; Redux or Context for global state | 2026-08-04 |
| 11 | decision | AD-6: CSS approach — CSS Modules (*.module.css) per component. Binds: styles are component-scoped; global tokens in /styles/globals.css (colors, fonts, spacing). Prevents: inline styles; global class name collisions; Tailwind | 2026-08-04 |
| 12 | decision | AD-7: Authentication boundary — Keycloak as sole auth provider; Next.js uses NextAuth.js with Keycloak OIDC adapter. Binds: all protected routes check session server-side; role extracted from Keycloak token (manager/officer/farmer); no custom auth logic in application. Prevents: client-side route-only protection; custom JWT implementation | 2026-08-04 |
| 13 | decision | AD-8: AI service isolation — Ollama and FastAPI are isolated I-layer services. Binds: Next.js API routes are the only callers; no direct browser-to-Ollama calls; OLLAMA_MODEL env var switches models (phi3 local / mistral server). Prevents: AI calls from client components; hardcoded model names in business logic | 2026-08-04 |
| 14 | decision | AD-9: Data pipeline ownership — n8n owns all external API ingestion (USDA, WTO, NASA POWER, Open-Meteo, ExchangeRate). Binds: n8n writes to PostgreSQL; Next.js reads only; no Next.js code calls external data APIs directly. Prevents: rate limit exposure; duplicate ingestion logic | 2026-08-04 |
| 15 | decision | AD-10: Map rendering boundary — All map rendering is client-side only ('use client'). Binds: Leaflet components wrapped in dynamic import with ssr:false; Turf.js calculations run client-side for polygon area; Nominatim called server-side via API route to avoid CORS. Prevents: SSR hydration mismatch with Leaflet | 2026-08-04 |
| 16 | decision | AD-11: Notification architecture — Web Bell is server-sent (Next.js API route + polling or SSE); n8n handles external push (Mattermost post-30/8). Binds: notifications stored in PostgreSQL notifications table; each actor polls or receives SSE for their notifications. Prevents: WebSocket complexity for MVP; n8n as the only external push path | 2026-08-04 |
| 17 | decision | AD-12: File storage boundary — MinIO is the sole file store (disease photos, P.A.R.A documents, generated QR assets). Binds: Next.js accesses MinIO via pre-signed URLs only; no direct MinIO SDK in client components. Prevents: files stored in PostgreSQL; public MinIO bucket exposure | 2026-08-04 |
| 18 | decision | AD-13: Git workflow — GitHub Flow. Binds: main is always deployable; every feature/fix is a branch off main named feat/issue-N-slug or fix/issue-N-slug; merge only via Pull Request with at least 1 review. Prevents: long-lived develop branches; direct push to main | 2026-08-04 |
| 19 | decision | AD-14: Environment strategy — Three environments via Docker Compose env files: local (.env.local), staging (.env.staging), production (.env.production). Binds: OLLAMA_MODEL=phi3 for local; OLLAMA_MODEL=mistral for staging/production; no secrets committed to git. Prevents: hardcoded environment values in code | 2026-08-04 |
| 20 | decision | AD-15: Backend code structure — Next.js API routes follow domain-driven folder structure under /app/api/[domain]/. Binds: each domain owns its routes, service layer, and Prisma queries; no cross-domain direct imports (use shared /lib). Prevents: spaghetti API routes; business logic in route handlers | 2026-08-04 |
| 21 | decision | AD-16: SOLID application — Single Responsibility at service layer (one service class per domain); Open/Closed via strategy pattern for notification channels (Web Bell / Mattermost); Dependency Inversion via constructor injection in service classes. Prevents: god classes; direct instantiation of dependencies in business logic | 2026-08-04 |
| 22 | decision | AD-17: QR public page — statically generated (Next.js generateStaticParams or ISR) from lot data at QR export time. Binds: /lot/[lotCode]/page.tsx is a Server Component reading from PostgreSQL at build/revalidate; no client-side data fetch on public page. Prevents: slow QR scan load; authenticated-only lot data | 2026-08-04 |
